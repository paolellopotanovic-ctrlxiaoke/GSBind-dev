# Architecture and package boundaries

The public package is intentionally small:

- `src/m4/model.py`: stable model import.
- `src/m4/dataloader.py`: stable dataset, collation, and manifest imports.
- `src/m4/inputs.py`: strict unlabeled PDB-to-manifest conversion.
- `src/m4/predictor.py`: strict label-free per-residue prediction.
- `src/m4/trainer.py` and `evaluator.py`: validated training/evaluation entry points.
- `src/m4/cli.py`: one dispatcher for training, evaluation, inference, and caches.

`src/m4/legacy_repo` contains the dependency closure of the byte-validated
scientific implementation. Its original import layout is retained because a
cosmetic rewrite before numerical equivalence validation would weaken, not
improve, reproducibility. Public modules are facades and do not alter tensors,
checkpoint names, model forward behavior, losses, or optimization.

This project uses standard PyTorch training code, not PyTorch Lightning. The
experiment state, scheduler, AMP, gradient accumulation, checkpointing, and
evaluation loops are explicit in the validated trainer.

`eval` and `predict` are deliberately separate. `eval` consumes biological
labels and produces metrics. `predict` accepts manifests generated by
`prepare-input`, requires strict four-cache coverage, and only exports residue
probabilities plus provenance metadata.
